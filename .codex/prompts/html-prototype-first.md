# HTML Prototype First

Use this for new screens, redesigns, and premium UI direction changes.

Goal: explore premium UI quickly before touching React architecture.

Steps:

1. Build one standalone HTML prototype in `docs/prototypes/`.
2. Keep it inspectable in a browser without app state or backend dependencies.
3. Show the real screen structure, content density, states, and visual hierarchy.
4. Use lightweight CSS only; avoid framework setup and heavy animation.
5. Inspect desktop and mobile with Browser or Computer Use.
6. Carry only the approved direction into React/Vite.
7. Delete or archive stale prototypes when they stop matching the product.

Rules:

- Prototype is for direction, not production logic.
- Do not fake AI, uploads, OCR, or official verification in prototype copy.
- Do not call a React implementation premium if the prototype was not visually checked.
