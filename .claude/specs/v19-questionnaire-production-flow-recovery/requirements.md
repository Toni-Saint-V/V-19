# Требования: восстановление входа в анкету после создания подачи

## Контекст

- Рабочий источник поведения: `codex/v19-handoff-combined-release-20260726` (`939b4b5d`).
- Production baseline: `d79ac3f2175faad9e56597a02145c8e194a65ae4`.
- В production RPC успешно создаёт подачу и возвращает новую revision, но добавленный позднее принудительный raw canonical readback ложно отклоняет результат и не открывает анкету.

## Функциональные требования

1. WHEN агент создаёт новую подачу и `save_submission_draft` успешно возвращает новую revision, система SHALL открыть анкету созданной подачи.
2. WHEN UI принимает успешный ответ RPC, система SHALL сохранить новые owner/revision данные и выполнить штатный последующий canonical refresh.
3. WHEN транспортная ошибка или RPC-ошибка действительно произошла, система SHALL сохранить существующее fail-closed поведение и не объявлять сохранение успешным.
4. WHEN неоднозначный create повторяется, система SHALL продолжить использовать существующий pending submission id и не создавать дубликат.

## Ограничения

- Переносится только уже работающее поведение из `939b4b5d`.
- Не изменяются schema, RLS, RPC, lifecycle, questionnaire data model, стили и тестовые файлы.
- Проверка выполняется только через реальный UI: create → open questionnaire → exit → reopen → reload.
- Доказательство — свежие скриншоты; автоматические тестовые suites не используются.
